# hast

Converts an [mdast] tree into a [hast] tree — the HTML-shaped syntax tree the
rehype ecosystem uses.

## Purpose

A site rendering a Barbara page wants a tree it can render with no Markdown
tooling at all. An [mdast] tree is Markdown-shaped (`paragraph`, `emphasis`,
`listItem`); rendering it still means knowing Markdown semantics. A [hast] tree
is HTML-shaped — `element` nodes with a `tagName`, `properties`, and
`children` — so a renderer is a `switch` on `tagName`. This package produces
that tree in Go, and its JSON is **byte-equal** to what
[`mdast-util-to-hast`][to-hast] produces. That equality is the contract: any
renderer built for hast (`hast-util-to-html`, a framework component walker)
renders a Barbara page unchanged.

The package is a **leaf** — it imports [`internal/mdast`](../mdast) and the
standard library, nothing else in Barbara.

## Pieces

| Symbol | Role |
|--------|------|
| `FromMdast(root *mdast.MdastRoot) *HastRoot` | Converts an mdast tree into a hast tree. |
| `HastNode` | The closed node union. Its method is unexported, so only this package defines node types. |
| `HastRoot`, `HastElement`, `HastText`, `HastComment`, `HastRaw` | One struct per [hast][] content type. |

The Go type names carry a `Hast` prefix. rocco names a schema after the bare Go
type name, and both trees have a `root` and a `text` node, so the prefix keeps
the hast schemas distinct from the [`Mdast…`](../mdast) ones in the OpenAPI spec.
The JSON `type` values are the unprefixed hast names (`root`, `element`, `text`,
`comment`, `raw`).

## Two option deviations

The conversion reproduces `mdast-util-to-hast` at the version pinned in the web
workspace, with two changes from its default options. Both are configured
identically on the JavaScript side in
[`web/scripts/mdast-fixtures.mjs`](../../web/scripts/mdast-fixtures.mjs), so the
golden fixtures reflect them.

1. **Raw HTML is passed through.** An mdast `html` node becomes a hast `raw`
   node (the default drops it). This matches `format=mdast`, which also carries
   the raw HTML. A `raw` node is not standard hast: a consumer either emits it
   verbatim (trusted content) or runs it through an HTML parser
   (`hast-util-raw`) to turn it into elements. The consumer decides whether to
   sanitise.
2. **The code fence `meta` is kept.** The default mapping discards a fence's
   meta string. Instead it is set as the `dataMeta` property on the `<code>`
   element, which a renderer emits as a `data-meta` attribute. So a fence
   ```` ```go title="main.go" ```` reaches the client with its metadata intact.

Everything else matches the library: block children are separated by `"\n"` text
nodes, a tight list item's first paragraph is unwrapped, task items get a
disabled checkbox `<input>`, tables split into `<thead>`/`<tbody>`, footnotes
become a `<section class="footnotes">` with back references, and link and image
URLs are passed through `normalizeUri`.

## OpenAPI and the SDK

The published document lookup returns a page as a hast tree by default
(`GET /published/apps/{app_id}/lookup?key=…`, or `&format=hast`). The node types
carry rocco schema tags (a const `type`, a discriminated `children` union), so
the OpenAPI spec and the generated TypeScript SDK describe the tree as a typed,
discriminated union — the Go structs are the single source of truth. A test in
`api/handlers` validates every fixture against the generated schema, so the
structs and the schema cannot drift apart.

Link and image URLs are returned **as authored**. Rewriting them to published
routes (as `format=mdast` does) is deferred until the CDN layout is decided; see
#113 and #95.

## Testing

The golden fixtures live in [`../mdast/testdata/`](../mdast/testdata/), shared
with the mdast package: a `.md` file, its mdast `.json`, and its hast
`.hast.json`, all generated by
[`web/scripts/mdast-fixtures.mjs`](../../web/scripts/mdast-fixtures.mjs).
`TestFixtures` parses each `.md` to mdast, converts it with `FromMdast`, and
compares the JSON byte-for-byte with the `.hast.json`.
